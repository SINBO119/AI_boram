## 2. 문제

데이터가 자주 모자라는 고객은 매달 20일쯤 데이터가 떨어져 추가 요금을 내거나 충전한다. 이런 일이 3개월 이상 반복되면 요금제를 바꾸려 하지만, 다음 세 가지에서 막혀 결정을 미룬다.

1. 요금제가 너무 많아 혼란스럽다.
2. 늘어나는 요금만큼 혜택이 정말 이득인지 판단하기 어렵다.
3. 바꾼 뒤에도 데이터가 모자라 또 사야 하지 않을지 걱정된다.

## 3. 목표

- 고객의 **실제 사용량**을 근거로, 데이터가 충분한 요금제를 2~3개로 좁혀 보여 준다.
- 현재 요금제와 비교해 **요금이 크게 오르지 않고(+20% 이내)** **혜택이 줄지 않는지**를 한눈에 보여 준다.
- 바꾼 뒤에도 데이터가 모자랄 수 있는 경우를 미리 알려 준다.

**성공 지표**: 미정. 인터뷰에서 다루지 않았습니다(Q12).

## 5. 범위

### 포함
- 요금제 추천 (분기 A / B / C)
- 요금제 목록 (등급별)
- 요금제 상세 (현재 요금제와 비교)

### 제외
- 구독 신청, 결제, 약관 동의, 신청 완료(저장)

## 6. 화면과 기능 요구사항

### 6-1. 요금제 추천

진입하면 고객 데이터를 불러와 분기를 정한다.

| 조건 | 분기 |
|---|---|
| 현재 요금제가 완전 무제한 | **B** 혜택 기준 추천 |
| 현재 기본 제공량 ≥ 최대 사용량 | **C** 현재 유지 안내 |
| 그 외 | **A** 사용량 기준 추천 |

**A. 사용량 기준 추천** (US1, US2, US4)

| ID | 요구사항 |
|---|---|
| F-A1 | 기준 기간(최근 3개월)의 월별 사용량과 최대 사용량을 보여 준다. |
| F-A2 | 이력이 3개월보다 짧으면 있는 만큼으로 계산하고, 이력이 짧다고 알린다. |
| F-A3 | 후보는 **데이터 충분**(R2)하고 **할인 후 실납부액 ≤ 요금 상한**(R3)인 요금제다. |
| F-A4 | 최적 요금제 1개를 "추천"으로 표시한다. **가정:** 후보 중 실납부액이 가장 낮은 것 (Q2). |
| F-A5 | 대안으로 한 단계 위 요금제와 한 단계 아래 요금제를 보여 준다(최대 2개). **가정:** "단계"는 기본 제공량 순서 (Q3). 대안에도 상한을 적용할지는 미정 (Q4). |
| F-A6 | 한 단계 아래 대안은 기본 제공량 ≥ 평균 사용량일 때만 보여 주고, "가장 많이 쓴 달에는 모자랄 수 있음"을 표시한다. |
| F-A7 | 후보가 없으면 데이터가 충분한 요금제 중 실납부액이 가장 낮은 것을 추천하고, "현재보다 20% 넘게 올라요"를 알린다. |
| F-A8 | 추천 카드마다 월정액, 할인 후 실납부액, 기본 제공량(QoS면 속도 제한 표시), 추가 혜택, 현재 대비 요금 차이를 보여 준다. |
| F-A9 | 사라지는 혜택이 있으면 카드에 경고로 표시한다. |

**B. 혜택 기준 추천** (US5)

| ID | 요구사항 |
|---|---|
| F-B1 | 사용량은 근거로 쓰지 않는다. |
| F-B2 | 원하는 혜택(제휴 구독 / 멤버십·할인)을 고객이 고르게 한다. 여러 개를 고를 수 있는지는 미정 (Q6). |
| F-B3 | 후보는 지금 쓰는 요금제가 아닌 **다른 완전 무제한 요금제** 중, 고른 혜택이 있고 실납부액 ≤ 요금 상한인 것이다. |
| F-B4 | 보여 줄 개수, 정렬, 후보가 없을 때의 처리는 미정 (Q6). |

**C. 현재 유지 안내** (US6)

| ID | 요구사항 |
|---|---|
| F-C1 | "지금 요금제가 적합해요"와 최대 사용량, 현재 기본 제공량을 보여 준다. |
| F-C2 | 목록으로 이동할 수 있는지는 미정 (Q8). |

### 6-2. 요금제 목록 (US7)

| ID | 요구사항 |
|---|---|
| F-L1 | 등급 필터 칩: 전체 / 베이직 / 스탠다드 / 프리미엄. 기본 선택은 전체. |
| F-L2 | 등급은 기본 제공량 구간으로 나눈다. 구간 값은 미정 (Q1). |
| F-L3 | 요금제 카드에 이름, 월정액, 할인 후 실납부액, 기본 제공량, 추가 혜택을 보여 준다. |
| F-L4 | 카드를 선택하면 요금제 상세로 이동한다. |

### 6-3. 요금제 상세 (US3, US4)

| ID | 요구사항 |
|---|---|
| F-D1 | 선택한 요금제와 현재 요금제를 나란히 비교한다: 월정액, 할인 후 실납부액, 기본 제공량, 추가 혜택. |
| F-D2 | 최대 사용량 대비 데이터가 충분한지 표시한다. |
| F-D3 | 실납부액 차이와 요금 상한(+20%)을 넘는지 표시한다. |
| F-D4 | 사라지는 혜택을 경고로 표시한다. |
| F-D5 | QoS 요금제는 기본 제공량과 그 뒤의 제한 속도를 함께 표시한다. |
| F-D6 | 다른 요금제를 비교하려면 추천으로 돌아간다. |
| F-D7 | 신청 버튼의 존재 여부와 동작은 이번 범위 밖이다. 시안의 "구독 신청" 버튼 처리는 미정 (Q13). |

## 7. 비즈니스 규칙

DOMAIN.md 5장의 R1~R12를 따른다. 그중 화면 동작에 직접 영향을 주는 규칙은 다음과 같다.

- **R1** 적정 데이터량 = 기준 기간 중 최대 사용량
- **R2** 데이터 충분 = 기본 제공량 ≥ 최대 사용량 (완전 무제한은 항상 충분, QoS는 기본 제공량만으로 판단)
- **R3** 요금 상한 = 현재 할인 후 실납부액 × 1.2
- **R4** 추천 요금제의 실납부액 = 지금 받는 할인을 종류별로 다시 적용 (비율 할인은 같은 비율, 정액 할인은 같은 금액)
- **R11** 화면에는 월정액과 실납부액을 둘 다 표시

**계산 예시** (가상의 수치)
- 월별 사용량 18 / 25 / 22 GB → 최대 25 GB, 평균 약 21.7 GB
- 현재 실납부액 50,000원 → 요금 상한 60,000원
- 후보 조건: 기본 제공량 ≥ 25 GB이고 실납부액 ≤ 60,000원
- 한 단계 아래 대안: 기본 제공량 ≥ 21.7 GB일 때만 넣고, 모자랄 수 있다고 경고

## 8. 데이터 요구사항

| 데이터 | 용도 |
|---|---|
| 월별 데이터 사용량 | 최대·평균 사용량, 분기 판단 |
| 현재 요금제 | 분기 판단, 비교 기준 |
| 적용 중 할인 (종류, 비율/정액, 값) | 실납부액, 요금 상한 계산 |
| 이용 중 혜택 | 사라지는 혜택 판단 |
| 요금제 마스터 (월정액, 데이터 유형, 기본 제공량, QoS 속도, 등급, 혜택) | 후보 선정, 목록, 상세 |

엔티티 관계는 DOMAIN.md 6장을 따른다. 고객은 고객 ID로만 식별하며, 화면에 개인정보를 표시하지 않는다.

**화면 상태** (로딩 / 빈 / 에러): 데이터 조회가 실패했을 때와 요금제가 하나도 없을 때의 표현은 미정 (Q14).
