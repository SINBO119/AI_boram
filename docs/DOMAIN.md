## 1. 배경

- **무엇을**: 요금제 추천·구독 서비스 모바일 웹의 요금제 선택 화면(추천, 목록, 상세)
- **누구를 위해**: 데이터가 자주 모자라는 기존 가입자
- **왜**: 매달 20일쯤 데이터가 떨어져 추가 요금을 내거나 충전하는 일이 3개월 이상 반복되면 고객은 요금제를 바꾸려 한다. 하지만 요금제가 너무 많고, 바꾸는 게 이득인지, 바꾼 뒤에도 모자라지 않을지 판단하기 어려워 결정을 미룬다.
- **목표**: 고객의 실제 사용량을 근거로 "데이터는 충분하고, 요금은 크게 오르지 않고, 혜택은 줄지 않는다"를 보여 주어 확신을 갖고 고르게 한다.

## 2. 용어집

| 용어 | 정의 |
|---|---|
| 기존 가입자 | 현재 요금제와 사용 이력이 있는 고객. 이번 범위의 유일한 사용자 |
| 월별 데이터 사용량 | 고객이 달마다 사용한 데이터량(GB) |
| 기준 기간 | 최근 3개월. 이력이 3개월보다 짧으면 있는 만큼만 씀 |
| 최대 사용량 | 기준 기간 중 가장 많이 쓴 달의 사용량. **적정 데이터량**의 기준 |
| 평균 사용량 | 기준 기간 월별 사용량의 평균. 하위 대안을 넣을지 판단할 때만 씀 |
| 기본 제공량 | 요금제가 매달 제공하는 데이터량(GB). 속도 제한 요금제는 제한이 걸리기 전까지의 양 |
| 완전 무제한 요금제 | 데이터 제한이 없는 요금제. 추천 후보로서 데이터 조건을 항상 충족함 |
| 속도 제한(QoS) 요금제 | 기본 제공량을 다 쓴 뒤 속도를 낮춰 계속 쓸 수 있게 하는 요금제. 데이터 충분 여부는 **기본 제공량만**으로 판단 |
| 데이터 충분 | 후보 요금제의 기본 제공량 ≥ 최대 사용량 (완전 무제한은 항상 충분) |
| 월정액 | 할인 전 요금제 기본 금액(정가) |
| 할인 후 실납부액 | 월정액에서 고객에게 적용되는 할인을 뺀 금액. **요금 비교와 상한 계산의 기준** |
| 적용 중 할인 | 고객이 지금 받는 약정·결합 등의 할인. 비율 할인과 정액 할인이 있음 |
| 요금 상한 | 현재 요금제의 할인 후 실납부액 × 1.2 (+20%) |
| 추가 혜택 | 요금제에 딸린 **제휴 구독 혜택**과 **멤버십·할인** (통화·문자, 테더링·쉐어링은 포함하지 않음) |
| 사라지는 혜택 | 현재 요금제에는 있고 추천 요금제에는 없는 추가 혜택 |
| 최적 요금제 | 추천 결과 중 대표로 표시하는 1개 |
| 대안 요금제 | 최적 요금제의 한 단계 아래나 위 요금제 |
| 등급 | 목록 화면의 분류. 베이직 / 스탠다드 / 프리미엄. 데이터량 구간으로 나눔 |

**같은 말을 다르게 쓰는 경우**
- "요금"이라는 말이 월정액을 뜻할 때도, 할인 후 실납부액을 뜻할 때도 있다. 계산은 항상 **할인 후 실납부액**으로 하고, 화면에는 둘 다 보여 준다.
- "데이터량"이라는 말이 고객이 **쓴 양**(사용량)을 뜻할 때도, 요금제가 **주는 양**(기본 제공량)을 뜻할 때도 있다. 둘을 구분해서 쓴다.
- screens.md 시안의 "이용 횟수"(월 10회/30회)는 이 도메인에서 쓰지 않는다. 요금제는 **데이터량(GB)** 기준이다.

## 3. 사용자와 역할

| 역할 | 목표 |
|---|---|
| 데이터가 모자라는 기존 가입자 | 추가 요금 없이 쓸 수 있으면서 요금이 크게 오르지 않는 요금제를 찾는다 |
| 데이터가 남는 기존 가입자 | 지금 요금제를 그대로 써도 되는지 확인한다 |
| 지금 완전 무제한을 쓰는 기존 가입자 | 원하는 혜택이 있는 다른 무제한 요금제를 찾는다 |

## 4. 핵심 흐름

### 4-1. 추천 분기

```
기존 가입자 진입 (로그인된 상태로 가정)
 └ 월별 사용량, 현재 요금제, 적용 중 할인, 이용 중 혜택을 불러옴
     ├ 현재 요금제가 완전 무제한인 경우 → [B] 혜택 기준 추천
     ├ 현재 기본 제공량 ≥ 최대 사용량인 경우 → [C] 현재 유지 안내
     └ 그 외 → [A] 사용량 기준 추천
```

### 4-2. [A] 사용량 기준 추천

1. 최대 사용량, 평균 사용량, 요금 상한을 계산한다.
2. **후보**: 데이터가 충분하고, 할인 후 실납부액이 요금 상한 이하인 요금제.
3. **최적 요금제 1개**를 고른다.
4. **대안**(최대 2개)
   - 한 단계 위 요금제
   - 한 단계 아래 요금제: 기본 제공량이 평균 사용량 이상일 때만 넣고, "가장 많이 쓴 달에는 모자랄 수 있음"을 표시
5. 후보가 없으면 **데이터를 우선**한다. 데이터가 충분한 요금제 중 실납부액이 가장 낮은 것을 추천하고, 요금 상한을 넘었다는 사실을 알린다.
6. 추천 요금제마다 현재 요금제와 비교해 보여 준다: 월정액, 할인 후 실납부액, 기본 제공량, 추가 혜택.
7. 사라지는 혜택이 있어도 추천은 하되, 경고로 표시한다.

### 4-3. [B] 혜택 기준 추천 (지금 완전 무제한을 쓰는 고객)

1. 사용량은 근거로 쓰지 않는다.
2. 고객에게 원하는 혜택을 묻는다.
3. **후보**: 지금 쓰는 요금제가 아닌 다른 완전 무제한 요금제 중, 원하는 혜택이 있고 할인 후 실납부액이 요금 상한 이하인 것.

### 4-4. [C] 현재 유지 안내

- "지금 요금제가 적합해요"라고 안내한다.

### 4-5. 목록과 상세

- **목록**: 요금제를 등급(베이직 / 스탠다드 / 프리미엄)으로 나눠 보여 준다. 추천 대신 직접 둘러보려는 고객이 쓴다.
- **상세**: 선택한 요금제를 현재 요금제와 비교해 보여 준다. 월정액, 할인 후 실납부액, 기본 제공량(QoS 여부), 추가 혜택, 사라지는 혜택, 데이터 충분 여부.

### 4-6. 예외 상황

| 상황 | 처리 |
|---|---|
| 사용 이력이 3개월보다 짧음 | 있는 이력만으로 최대·평균을 계산하고, 이력이 짧다고 알린다 |
| 상한 안에 데이터가 충분한 요금제가 없음 | 데이터를 우선해 추천하고, 상한을 넘었다고 알린다 (4-2의 5번) |
| 하위 대안이 평균 사용량보다 적음 | 대안에서 뺀다 |
| 추천 요금제에서 혜택이 사라짐 | 추천하되 경고로 표시한다 |
| 지금 완전 무제한을 씀 | [B] 혜택 기준 추천으로 처리한다 |
| 데이터가 남음 | [C] 현재 유지 안내로 처리한다 |

## 5. 비즈니스 규칙

| ID | 규칙 |
|---|---|
| R1 | 적정 데이터량은 기준 기간(최근 3개월, 이력이 짧으면 있는 만큼)의 **최대 사용량**으로 정한다 |
| R2 | 데이터 충분: 기본 제공량 ≥ 최대 사용량. 완전 무제한은 항상 충분, QoS 요금제는 기본 제공량만으로 판단한다 |
| R3 | 요금 상한 = 현재 요금제의 할인 후 실납부액 × 1.2 |
| R4 | 추천 요금제의 할인 후 실납부액은 지금 받는 할인을 **종류별로** 다시 적용해 계산한다 (비율 할인은 같은 비율, 정액 할인은 같은 금액) |
| R5 | 추천 결과는 2~3개: 최적 1개 + 대안(한 단계 위 / 한 단계 아래) |
| R6 | 한 단계 아래 대안은 기본 제공량 ≥ 평균 사용량일 때만 넣고, 모자랄 수 있다고 표시한다 |
| R7 | 상한 안에 후보가 없으면 데이터를 우선해 추천하고, 상한을 넘었다고 알린다 |
| R8 | 사라지는 혜택이 있는 요금제도 추천하되, 경고로 표시한다 |
| R9 | 지금 완전 무제한을 쓰는 고객에게는 사용량으로 추천하지 않는다. 원하는 혜택을 기준으로 다른 완전 무제한 요금제만 추천하고, R3 상한을 적용한다 |
| R10 | 현재 기본 제공량 ≥ 최대 사용량이면 현재 유지를 안내한다 |
| R11 | 화면에는 월정액과 할인 후 실납부액을 둘 다 표시한다 |
| R12 | 목록의 등급은 기본 제공량 구간으로 나눈다 |

## 6. 데이터 모델

```
Customer (기존 가입자)
 ├─ 1 : 1  CurrentSubscription ── N : 1 ── Plan
 ├─ 1 : N  MonthlyUsage
 ├─ 1 : N  AppliedDiscount
 └─ 1 : N  ActiveBenefit ── N : 1 ── Benefit

Plan ── N : M ── Benefit
```

| 엔티티 | 주요 속성 | 비고 |
|---|---|---|
| Customer | 고객 ID | 이 서비스는 고객 ID 외의 개인정보를 쓰지 않음 |
| MonthlyUsage | 고객 ID, 연월, 사용량(GB) | 기준 기간 계산에 씀 |
| Plan | 요금제 ID, 이름, 월정액, 데이터 유형(정량 / QoS / 완전 무제한), 기본 제공량(GB), QoS 속도, 등급 | 등급은 기본 제공량 구간으로 정해짐 |
| CurrentSubscription | 고객 ID, 요금제 ID | |
| AppliedDiscount | 고객 ID, 할인 종류, 방식(비율 / 정액), 값 | R4 계산에 씀 |
| Benefit | 혜택 ID, 이름, 종류(제휴 구독 / 멤버십·할인) | |
| ActiveBenefit | 고객 ID, 혜택 ID | 사라지는 혜택을 판단할 때 씀 |

**계산 값** (저장하지 않음): 최대 사용량, 평균 사용량, 이력 개월 수, 현재 실납부액, 요금 상한, 후보 실납부액, 데이터 충분 여부, 사라지는 혜택.

## 7. 이번 범위에서 하지 않을 것

- 구독 신청, 결제, 약관 동의, 신청 완료(저장)
- 로그인, 회원가입 (로그인된 기존 가입자라고 가정함)
- 신규 가입자(사용 이력이 없는 고객) 추천 — 대상 고객을 "기존 가입자"로 정했으므로 빠짐. **확인 필요** (열린 질문 Q10)
- 마이페이지, 구독 현황 — 화면 범위(추천+목록+상세)에서 빠짐. **확인 필요** (열린 질문 Q10)
- 이용 횟수 기준 요금제 (screens.md 시안의 횟수형)
